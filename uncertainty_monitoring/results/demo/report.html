Interpretation

The uncertainty policy tests detection gain and error gain for all three intensities against independently calibrated binomial rate intervals. Calibration uncertainty and all predeclared tests share the run budget. The bound requires stationary independent count trials within each supported context and correct telemetry. It is not a cryptographic security probability.

Fixed thresholds are transparent engineering defaults, not a baseline matched for false-alarm rate or sensitivity. The pointwise ablation uses the same contexts and six count features, with plug-in calibration rates and per-window correction. It has no claimed whole-run error guarantee. Zero holds can also mean missed events: inspect detection and latency together. Benign windows held include recovery after genuine events. Event-detection percentages apply only to sustained unexplained physical shifts; off-grid powers and missing reports require inconclusive handling. Delays exclude missed events, which remain in the event denominator. Channel events within a run are correlated; no binomial confidence interval is claimed for pooled channel-event detection.

Limits and reproducibility

WDM coupling coefficients are illustrative, not measured hardware data. Power contexts are discrete and measured without error in this stage. Shared-detector effects, real device commands, finite-key distillation, authenticated transport, and attack attribution are outside this implementation. Telemetry continues during advisory hold for recovery assessment.
